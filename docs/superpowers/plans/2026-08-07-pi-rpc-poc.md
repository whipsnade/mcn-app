# Pi RPC POC Implementation Plan

> SUPERSEDED 说明（2026-08-13）：本文是 2026-08-07 的历史 POC 实施计划，正文不改写。
> 文中 `required_artifact_type`/「复用既有 Evidence、Builder、Artifact、Excel 与 BI 契约」

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在独立数据库中用 Pi RPC 直接调用 DataTap，并与当前 Runtime 使用同一模型完成六类对比验收，证明 Pi 可自主研究且能复用既有 Evidence、Builder、Artifact、Excel 与 BI 契约。

**Architecture:** Python POC runner 为每个 Run 启动一个无状态 Pi RPC 子进程；本地 TypeScript Extension 直接连接 DataTap MCP，并通过带单 Run 临时令牌的内部 HTTP 端点透明写入 Evidence、调用既有内部工具与发布服务。Pi 路径不接钱包；Current 基线路径保持原生产计费代码并只使用 POC 独立库中的一次性测试钱包。POC 不开发新的积分能力、License、管理端、正式前端或并发，所有数据只进入 `kol_insight_pi_poc`。

**Tech Stack:** Python 3.11/3.12、FastAPI、SQLAlchemy Async、MySQL 8、Node.js 20+、TypeScript、当前官方 Pi coding-agent、MCP TypeScript SDK、pytest、Vitest。

## Global Constraints

- 设计依据：`docs/superpowers/specs/2026-08-07-pi-agent-runtime-integration-design.md`。
- 仅执行方案 A；不得实现生产 Gateway、管理端、License、积分或方案 C。
- 当前 Runtime 与 Pi 必须使用完全相同的 provider、model、thinking level、问题、历史和日期窗口。
- 数据库必须精确为 `kol_insight_pi_poc`；检测到其他数据库名时立即拒绝运行。
- Pi 必须使用 `--mode rpc --no-session --no-builtin-tools --no-context-files`，关闭自动发现并只显式加载已审核 Extension/Skills。
- Pi 直接调用 DataTap；Extension 不得修改工具名、参数、原始结果或错误，也不得自动重试、拆分或切换工具。
- DataTap token、模型 key 和内部 Run token 不得写入 Prompt、Skill、事件、Artifact、fixture 或输出文件。
- 积分不属于 POC 评价指标，禁止读写真实用户钱包。Pi 路径不创建钱包，Pi 直连 MCP 产生的
  `AgentToolCall.points_reserved/points_settled` 恒为 0；Current 路径不得绕过既有计费，
  必须在 `kol_insight_pi_poc` 中使用一次性测试钱包执行真实 reserve/settle/release。
- 每个 runtime/case 使用独立用户；两侧写入相同的默认渠道权限。仅 Current 用户创建余额
  10,000 的 POC 测试钱包，保证余额不成为研究路径变量；其流水仅作真实性审计，不参与 Gate。
- 每个 Pi Run 最多 30 分钟、50 次模型决策；POC 并发固定为 1。
- 六类强类型产物必须继续使用既有 Builder 与 `ArtifactPublicationService`，不允许 Pi 手写 payload。
- 每项任务严格 TDD；只暂存本任务文件，不能把工作树中既有未提交文件混入 commit。
- Pi 包近期从 `badlogic/pi-mono`/旧 npm scope 迁移到 `earendil-works/pi`；Task 1 必须以官方当前发行版实测并锁版本，不得直接使用浮动 `latest`。

```ts
export type PiRpcRecord = { type: string; [key: string]: unknown };

export function parseRpcLine(line: string): PiRpcRecord {
  const normalized = line.endsWith("\r") ? line.slice(0, -1) : line;
  if (!normalized.trim()) throw new Error("empty_rpc_record");
  const value: unknown = JSON.parse(normalized);
  if (typeof value !== "object" || value === null || Array.isArray(value)) {
    throw new Error("invalid_rpc_record");
  }
  if (typeof (value as { type?: unknown }).type !== "string") {
    throw new Error("invalid_rpc_record");
  }
  return value as PiRpcRecord;
}
```
