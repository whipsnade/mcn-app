# 品牌分析报告导出与 BI 重构设计

日期：2026-07-30  
状态：已确认，待实施  
关联模板：`brand_report.xlsx`

## 背景与目标

当前品牌分析报告以通用 `ReportDocument`/Block 形式存储和展示，缺少稳定的品牌报告数据契约与导出能力。右侧 BI 能展示通用卡片、图表和表格，但不能稳定覆盖品牌经营分析所需的日趋势、地域、双平台热帖、舆情洞察与方法论。

本需求的目标：

1. 为每一版品牌分析报告提供零积分、可下载的 Excel 报告。
2. 右侧「品牌分析」改为与 Excel 模板章节一一对应的报告型 BI。
3. 保留既有「AI 结论」及「结论与建议」两张卡片，置于数据章节之后。
4. 让 BI 与导出文件消费同一个版本化数据快照，数值可追溯、历史版本不会因后续代码改动而变化。

## 已确认决策

- 采用结构化品牌报告 `brand_report_v2`，不采用仅重排通用 Block 或打开时临时重建两种方案。
- 采用模板章节式 BI（方案 B）：阅读顺序与 Excel Sheet 顺序一致。
- 数据不完整时允许生成受限报告；不以 0 填补、不编造趋势或结论，必须标明未取得的字段和原因。
- 导出的是当前选中的历史版本；导出过程不调用模型或 MCP，不计费。
- 模板中的示例品牌数据不作为运行时内容；需制作去样例的受控模板副本。

## 模板章节与数据契约

`brand_report_v2` 由以下顶层字段构成：

```text
template_version: "brand_report_v2"
data_status: complete | partial
scope: 品牌、关键词、时间窗、平台
data: 归一化且可追溯的数值与明细
narrative: 基于 data 生成的文本洞察
availability: 各章节的状态、缺失字段与原因
sources: 数据工具、采集时间与证据引用
```

其中 `data` 是唯一的数值事实来源，必须由服务端从本次目标已 settled 的 MCP 证据归一得到。`narrative` 只能引用 `data`；模型不得创造、换算或修改指标数值。

| 章节 / Excel Sheet | `data` 固定内容 | BI 呈现 |
|---|---|---|
| 综合概览 | 分析周期、品牌/关键词、数据源、各平台与合计指标、环比/同比、正中负构成 | 范围信息、KPI、平台对比、变化表、情感构成 |
| 情感分析 | 平台 × 情感的声量、互动数、占比；关键发现 | 堆叠情感图、对比表、发现卡片 |
| 日趋势 | 日期、声量、互动数、峰值/备注 | 双折线、峰值标记、可展开明细 |
| 内容类型与达人 | 内容类型、达人层级、自然/商单内容 | 内容与达人层级图、自然/商单占比 |
| 地域分布 | Top 20 地区的声量、互动数、占比 | 排名条形图、完整表格 |
| 热门帖子 TOP | 每平台 Top 15 的标题、作者、互动、阅读、赞评藏转、情感、达人层级、原帖链接 | 平台切换列表、标题展开、原帖跳转 |
| 舆情洞察 | 好评点、槽点、影响程度、扩张信号、噪音说明 | 正负洞察、风险等级、扩张信号 |
| 方法论 | 数据源、查询口径、时间窗、平台、采样、情感、噪音、同比环比定义、局限性 | 折叠的「数据说明与方法论」 |

### 口径规则

- 热门帖子只保留品牌相关内容，按互动量排序，每个平台最多 15 条。
- 地域最多 20 条；超过上限按声量降序截断。
- 统计周期不完整时必须保存 `data_as_of`，页面与导出文件显示「截至日期」；不输出不可靠的同比结论。
- 标题或原帖链接缺失时保留原始记录，将对应字段标为「未提供」，禁止拼接或猜测 URL。
- 每个章节在 `availability` 中记录：`complete`、`partial` 或 `unavailable`，并记录 `missing_fields`、`reason`、`source_tools` 与 `collected_at`。

## 后端设计

### 报告构建

新增独立的品牌报告组装层，职责分离如下：

1. `BrandReportDataAssembler`：读取当前目标的 settled MCP evidence，按工具输出做确定性归一化，生成 `brand_report_v2.data` 与 `availability`。
2. `BrandReportNarrativeBuilder`：把结构化数据作为唯一模型输入，生成好评点、负面洞察、扩张信号、AI 结论和结论与建议。
3. `AnalysisReportService`：将模板版本、结构化快照、叙事文本与原有报告元数据一起按当前 `(session_id, report_type, version)` 规则落库。

为避免把复杂业务结构塞入通用 Block，`AnalysisReport` 增加独立的 `payload_json` 与 `template_version` 字段。原 `blocks_json` 保留，供旧报告与其他报告类型兼容；新品牌报告仍可生成兼容性 Block，但 BI/Excel 的事实数据只读 `payload_json`。

旧的 `brand_analysis` 记录不回填、不修改。读取时若无 `brand_report_v2`，前端走现有通用 Block 渲染，并明确提示该历史版本不支持模板导出。

### 导出 API

新增品牌报告导出端点：

```text
GET /sessions/{session_id}/reports/{report_id}/export
```

- 只允许当前用户导出自己会话中的 `brand_analysis` 已完成/受限版本。
- 校验 `report_id` 与 `session_id` 的归属关系，防止跨会话和跨用户读取。
- 仅读取该记录已保存的 `brand_report_v2` 快照；不调用模型、MCP、任务执行器和积分系统。
- 以版本化、去样例的 8 Sheet Excel 模板为基础填充数据，保留模板版式、表头、数字格式与图表。
- 空章节保留 Sheet、列头和受限说明；模板加载、填充或导出失败时返回明确错误，绝不输出半截文件。
- 下载文件名：`{品牌}_品牌社媒分析报告_{开始日期}-{结束日期}_v{版本}.xlsx`。

## 右侧品牌分析 BI

### 页面骨架

```text
报告标题 / 品牌·周期·平台 / 版本下拉 / 数据状态 / 导出报告
章节导航：概览｜情感｜趋势｜内容与达人｜地域｜热帖｜舆情｜方法论

综合概览
情感分析
日趋势
内容类型与达人
地域分布
热门帖子 TOP
舆情洞察
方法论（折叠）
AI 结论
结论与建议
```

- 章节导航为同页锚点导航，点击滚动并高亮当前章节；不拆成 8 个独立 Tab，避免窄侧栏频繁切换导致阅读上下文丢失。
- 顶部保留现有版本下拉；切换版本时，章节内容、数据状态与导出目标必须同时切换。
- 表格在侧栏宽度不足时支持横向滚动；热门帖标题默认最多两行，展开后显示全文和原帖链接。
- 「AI 结论」与「结论与建议」沿用既有卡片视觉，置于全部数据章节之后：前者描述发生了什么，后者输出可执行动作。

### 数据受限状态

- 报告顶栏显示整体状态：完整或数据受限。
- 章节级状态显示受限标记、缺失项与原因；不隐藏空章节，避免用户误以为系统未分析该维度。
- 当趋势数据不可用时，趋势章节显示受限说明，禁止用 overview 中的局部变化字段伪造完整折线与跨期判断。

## 模板与渲染

- 将 `brand_report.xlsx` 的结构转为受版本控制的运行时模板；发布前移除示例品牌、示例数据及「Python openpyxl」等旧生成说明。
- Excel Sheet 顺序固定为：综合概览、情感分析、日趋势、内容类型与达人、地域分布、热门帖子TOP、舆情洞察、方法论。
- 图表数据引用导出工作簿内已填充的数据区域；趋势、地域等维度为空时不绘制误导性图表，改为受限说明。
- 模板中的数字、日期、百分比和来源说明遵循现有格式；品牌、周期、来源、方法论来自报告快照而非系统当前状态。

## 失败处理与兼容性

| 场景 | 处理 |
|---|---|
| 个别工具证据缺失 | 报告为 `partial`，其他章节照常生成，缺失章节显示原因 |
| 模板渲染失败 | 导出接口返回可识别错误；BI 继续可浏览 |
| 结构化载荷校验失败 | 报告构建失败并登记失败 Artifact，不保存不一致版本 |
| 旧版通用品牌报告 | 保持原 Block 展示，提示不支持模板导出 |
| 非本人报告或报告类型不符 | 返回 404/权限错误，不泄漏报告存在性 |

## 验证范围

1. 组装层：指标、Top 15/Top 20 截断、日期完整性、缺失字段、来源追溯。
2. 叙事层：模型只能引用结构化输入，缺失章节不能生成虚假数值。
3. 存储层：报告版本独立、历史快照不可变、旧版兼容。
4. 导出：8 个 Sheet、表头、数值、日期/百分比格式、图表数据范围、受限章节、文件名。
5. API：会话/用户隔离、类型校验、当前版本导出、无需积分且不触发 MCP。
6. 前端：章节锚点、版本切换、数据受限、热帖展开与链接、旧版降级提示、导出状态。
7. E2E：生成一版完整/一版受限报告，切换版本并下载，核对页面与 Excel 的关键指标一致。

## 非目标

- 不回填或改写既有历史品牌报告。
- 不改变活动分析和达人分析的展示或导出逻辑。
- 不在导出时重新采集数据、重新调用模型或扣除积分。
