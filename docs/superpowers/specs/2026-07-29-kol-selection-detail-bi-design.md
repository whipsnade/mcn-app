# 圈选达人详情 BI 弹窗设计

## 目标

在会话右侧 BI 的「达人 → 圈选达人」名单中，用户点击任一达人后打开居中详情弹窗。
弹窗展示该达人可核验的资料、受众画像、内容与互动趋势、评分维度以及最新 5 条热帖，
并提供公开主页与原帖链接。

详情采用名单版本级缓存：首次查询走真实 MCP 并按实际工具调用次数结算积分；同一名单版本
再次打开零积分读取缓存；用户主动点击“刷新数据”才重新调用 MCP。

## 范围与非目标

- 覆盖 `kol_selection_items` 中的所有达人，不局限于自动补全的 Top20。
- 保持当前名单、评分、收藏与 Excel 导出 API 行为不变。
- 不编造 MCP 未返回的数值或链接；缺失字段在界面显示“暂无数据”。
- 首版不做跨名单版本复用、定时刷新、无限热帖滚动或新的独立详情路由页面。

## 数据与服务设计

### 缓存实体

新增 `kol_selection_detail_views`，以 `(selection_set_id, platform, kol_uid)` 唯一：

- `selection_set_id/platform/kol_uid`：确保详情快照与当前名单版本一致。
- `detail_json`：经过白名单归一化后的达人详情与图表事实；不保存 MCP 原始响应。
- `posts_json`：按互动量排序的最近热帖，最多保存 5 条，每条为标题、发布时间、互动、点赞、
  评论、收藏、公开链接和平台。
- `fetched_at`：最后一次成功查询时间。
- `points_cost`：本次缓存写入消耗的实际积分，供审计和 UI 回显。
- `posts_degraded`：热帖获取降级标记。

该表不替代 `kol_selection_detail_snapshots`：后者继续服务自动 Top20 评分重算和趋势图；
新表服务用户主动查看的详情弹窗。

### API

新增会话归属校验后的详情端点：

- `GET /sessions/{session_id}/kol-selection/detail?set_id=&platform=&kol_uid=`
  - 校验名单版本归属、达人存在与当前用户会话归属。
  - 命中缓存返回 `source="cache"`、`points_cost=0`。
  - 未命中返回 `source="missing"` 和当前基础名单/Top20 快照可用数据，不扣分。
- `POST /sessions/{session_id}/kol-selection/detail/query`
  - 请求体为 `set_id/platform/kol_uid/refresh`。
  - `refresh=false` 时先读缓存；命中直接返回零积分缓存。
  - 缓存未命中或 `refresh=true` 时复用 `QuickService.kol_detail` 的真实模型驱动 MCP 小循环，
    按现有 `QuickCallService` 预留/结算积分，成功后归一化并 upsert 缓存。
  - 返回实际 `points_cost`、缓存状态、详情和 5 条热帖。
  - 余额不足返回现有 `INSUFFICIENT_POINTS`；上游失败返回 `QUICK_CALL_FAILED`，不写覆盖旧缓存。

首次点击打开弹窗后调用 `POST`（缓存命中不会产生 MCP 调用）；用户点击“刷新数据”传
`refresh=true`。`GET` 用于加载已有缓存和恢复 UI，避免重新请求时闪烁。

### 详情归一化

沿用快捷详情的工具白名单与 `KolDetailFeatureResult`，并在新服务层输出稳定 DTO：

- 基础：昵称、平台、公开主页、粉丝、城市、报价、互动率。
- 画像：年龄分布、地区分布、兴趣分布。
- 内容：近 30 天平均互动、内容数、综合内容评分、趋势点。
- 评分：沿用名单的 v2 `score_json`，不在详情请求中重新修改名单评分。
- 热帖：最多 5 条；`url` 为空时不渲染链接；帖子标题为空显示“无标题”。

若当前名单已有 Top20 快照，`GET` 将其安全事实并入基础 DTO；主动详情查询的结果优先覆盖
同名非空字段。该合并只影响详情缓存，不修改名单原始事实。

## 前端交互与视觉设计

### 入口与弹窗

`KolSelectionCard` 整卡可点击，收藏按钮和公开链接阻止冒泡。键盘支持 Enter/Space 打开。
打开后展示 960px（小屏全宽）的居中模态框，遮罩可关闭，Esc 关闭，焦点留在弹窗内并在关闭后
返回触发卡片。

弹窗由四个区块组成：

1. **头部**：头像、昵称、平台、综合评分/评级、缓存状态、最后更新时间、公开主页链接、
   刷新按钮与关闭按钮。
2. **概览与评分**：粉丝、报价、互动率、近 30 天平均互动、数据完整度；八维评分以紧凑
   横向条展示权重、得分和缺失说明。
3. **受众与内容 BI**：年龄分布柱图、地区 Top10 横向条图、兴趣标签/占比，以及互动趋势
   折线图；无趋势点时保留图表容器并展示“暂无趋势数据”。
4. **最新热帖**：5 条卡片，含标题、发布时间、互动/点赞/评论/收藏和“查看原帖”外链。

桌面采用两列栅格、移动端折叠为单列。颜色沿用现有靛蓝主色、绿色数据成功态、琥珀色降级态、
玫瑰色错误态；图表使用项目既有 Recharts，避免新增可视化依赖。

### 状态与提示

- **缓存命中**：头部显示“缓存数据”，不显示扣分提示。
- **首次查询/刷新**：骨架屏覆盖图表区域，显示“正在查询达人详情”，完成后显示实际积分。
- **部分数据**：每个受影响模块独立提示，不阻断其他已返回模块。
- **热帖降级**：保留详情区，热帖区提示数据暂不可用。
- **积分不足/服务失败**：保留已缓存的旧数据，顶部呈现可操作的错误提示；没有缓存时显示空态与重试。

## 兼容性与安全

- 所有读写端点以当前用户、会话与名单版本三层校验，禁止跨用户读取缓存。
- 不向前端返回 MCP 原始响应、调用凭证或内部工具参数。
- 公开链接仅以归一化后的 `profile_url` / 帖子 `url` 输出，采用 `target="_blank"`
  与 `rel="noreferrer"`。
- 缓存仅在成功完整写入后更新；刷新失败时维持上一份缓存。

## 测试与验收

后端：

- 缓存未命中调用 MCP、结算积分并写入详情与 5 条热帖。
- 缓存命中零 MCP 调用、零积分，刷新强制重新查询。
- 跨用户/跨会话/不属于当前 selection set 的达人全部拒绝。
- 积分不足、上游失败、热帖降级均不覆盖旧缓存。
- 详情归一化只输出白名单字段，Top20 快照可作为基础数据回填。

前端：

- 点击名单卡片打开 A 型居中弹窗，收藏与链接点击不触发打开。
- 缓存、加载、错误、降级及刷新状态正确展示。
- 可访问性：Dialog 语义、Esc、焦点管理、键盘打开与关闭。
- 图表与 5 条热帖在完整/缺失数据下均稳定渲染；链接安全属性完整。

验收：用户首次打开未缓存达人后看到完整详情与实际积分；再次打开同一名单版本不扣分；刷新后
数据更新时间变化；可打开达人主页与存在链接的原帖。
