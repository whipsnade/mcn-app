### 事故与根因

- 会话「星巴克声量情感分析」brand_analysis Goal 失败：模型第 3 轮决策把
  `internal_tool_name` **误嵌进 `arguments` 内部**（顶层 null）→ `AGENT_TOOL_MISSING`；
  回喂文案笼统（「未通过校验」）模型无修正线索原样重犯 → 第 2 次熔断 → Goal 失败，
  已采集的标签与概览证据全部丢弃（原架构无「goal 失败但有部分证据」的降级路径）。
- 独立问题：brainstorm/GoalPlanner 的 prompt 与 payload 均无当前日期锚点，模型把
  「最近 1 个月」折算为 2025-12-01~2026-01-01（实际 2026-07-27），
  `param_profile_period_override` 无条件覆写放大错误。
- 按用户提供的修复计划实施。设计：`docs/superpowers/specs/2026-07-28-recoverable-decision-and-limited-report-design.md`；
  计划：`docs/superpowers/plans/2026-07-28-recoverable-decision-and-limited-report.md`。
  分支 `feat/recoverable-decision-limited-report`。

### 主要改动

1. **错误码拆分**（`orchestration/loop.py`）：`AGENT_DECISION_MISSING_TOOL_NAME`
   （顶层缺工具名，含误嵌 arguments 形态）与 `TOOL_NOT_ALLOWED` 分离。
2. **可恢复修正**（`tasks/executor.py`）：缺名决策独立计数（上限 2，校验成功双计数器
   清零），≤2 次回喂结构化 EvidenceNote（错因 + 误嵌点名 + 允许工具清单 + goal 目标
   提示），**不调 MCP、不扣积分、不占 invalid_streak**；其他 PlanValidationError
   熔断行为不变。
3. **修正耗尽受限交付**（单 goal 路径）：有 settled 证据 → goal
   `completed_with_warnings` + `warning_code=brand_trend_data_unavailable`，走既有
   `finalize_goal` 单入口（plan 评审修正：不得直接调 `_finalize_analysis_goal` 防
   重复构建），任务 reason `decision_recovery_exhausted` + 用户消息「部分数据未能
   获取，已基于已采集数据生成报告。」；零证据维持失败。**编排路径**按失败收尾
   （评审发现原实现会静默完成，已修为 failed + 不写 KOL 专用空结论）。
4. **受限声明**（`reporting/builders.py` + prompts）：warning_code 经
   `finalize_goal → _finalize_analysis_goal → builder` 透传，命中
   `_LIMITATION_NOTES` 映射时报告 prompt 注入「已完成品牌概览与情感快照；
   趋势数据未成功获取，不输出跨期趋势结论；不得按 overview 环比伪造」。
5. **brand_loop 强化**：`internal_tool_name` 顶层必填禁嵌 arguments、只有完整工具名
   才 call_tool、阶段工具顺序（标签→概览→趋势→话题/受众）、趋势优先
   social.statistic.trend；循环 payload 每轮注入 `called_tools`（settled 去重保序）
   与 `evidence_gaps`（brand 阶段清单减已覆盖，legacy 与编排路径共用）。
6. **日期锚点**：brainstorm 与 GoalPlanner payload 注入 `current_date`，两个 prompt
   各加折算规则；`param_profile_period_override` 拒绝未来窗口与 >400 天前窗口
   （保护活动复盘旧窗口），拒绝时回退代码解析窗口。

## 快捷页面状态缓存（QuickFeatureCache）+ 终审修复

### 背景与目标

右侧四个快捷页面（小红书爆贴、抖音爆贴、达人推荐、活动评估）此前把查询结果与表单
状态放在面板组件本地 state：切换快捷 Tab 时面板被卸载，结果全部丢失，切回后用户需
重新查询（每次 MCP 调用固定 10 积分，达人推荐约 20 积分），既费积分又打断操作流。

目标：切 Tab 不丢状态、不重复请求，缓存按用户隔离，不做跨用户/跨会话持久化，无后端
变更。设计：`docs/superpowers/specs/2026-07-28-quick-tab-state-cache-design.md`；
计划：`docs/superpowers/plans/2026-07-28-quick-tab-state-cache.md`。
分支 `codex/quick-tabs-cache`。

### 主要改动

1. **新增 `src/state/QuickFeatureCache.tsx`**：`QuickFeatureCacheProvider` 以
   `userId` 为 key 持有缓存（userId 变化即渲染期同步重置，杜绝跨用户泄露），缓存
   范围四类状态——爆贴结果（`topPosts`，按 platform 分键，小红书/抖音独立）、
   达人推荐（预算 + 名单 + 积分消耗）、活动评估（活动名 + 达人名单 + 未提交草稿 +
   报告）。`queryTopPosts`/`queryKolRecommendations` 入 Provider，按平台/按预算递增
   请求序号抑制过期响应；查询失败保留旧列表只更新错误（与迁移前面板行为一致）。
2. **三个面板迁移**：`TopPostsPanel`（爆贴两平台复用，读 `topPosts[platform]`）、
   `KolRecommendPanel`（预算/名单/积分入缓存，800ms 防抖保留）、`EvaluatePanel`
   （表单与报告入缓存，提交时快照参数，请求期间卸载不丢结果）；
   loading/submitting/收藏 busy 等瞬态仍留面板本地。
3. **Provider 挂载（终审修复）**（`src/App.tsx`）：`QuickFeatureCacheProvider` 挂在
   「activeSession || 快捷 Tab」条件块**外**。此前挂在条件块内，零会话用户在快捷
   Tab 查询后切到「智能会话/已收藏」，整个条件块（含 Provider）卸载，缓存全丢；
   快捷功能按设计是不绑定会话的全局功能，Provider 上移后仅条件块内容随 Tab 卸载。
4. **达人推荐防抖丢失补查（终审修复）**：缓存 entry 新增 `queriedBudget`（
   `queryKolRecommendations` 成功/失败回写本次实际请求的预算，回写保留用户当前
   预算不再覆盖）。此前拖预算后 800ms 防抖期内切 Tab，防抖 timer 随卸载被清理、
   查询从未发出；切回后 mount 级 `lastQueryKey` ref 以缓存中的新预算初始化，
   effect 判定相等直接 return，永远不重查（滑动条新预算 + 列表旧预算结果）。
   面板 effect 改为比较 `budget !== queriedBudget`：重挂载后发现「缓存预算 ≠
   已查询预算」走防抖补查一次；nonce ref 仅作同次挂载内手动刷新去重。
5. **集成回归**（`src/App.test.tsx`）：最小 Tab 容器 harness（Provider + 真实四
   面板）覆盖四 Tab 状态共存不重复请求；新增真实 App 级测试（mock auth/workspace
   与重组件，保留 WorkspaceTabs/KolRecommendPanel/Provider 为真实组件）复刻
   「会话删除 → 快捷 Tab 查询 → 切智能会话空态 → 恢复会话切回」，断言缓存不丢、
   不重复请求。`KolRecommendPanel.test.tsx` 新增防抖期内卸载再切回的补查用例；
   `QuickFeatureCache.test.tsx` 新增 `queriedBudget` 成功/失败回写用例。

无后端变更，无 API 契约变更。
