## Task 3：Run Skill Snapshot 与恢复不变性

### 背景与目标

让新 Pi Run 在创建时解析数据库 Activation 并冻结 Skill manifest；existing Run、child Run、resume/recovery 只验证并复用已持久化快照，不重新读取当前激活指针。

### 主要改动

- 新增 `backend/app/marketing_skills/snapshot.py`，提供冻结的 `SkillManifestEntry/SkillManifest`、manifest digest 校验和 DB Revision → `MarketingRunCapability` 解析。
- `RuntimeConfigSnapshot` 增加可选 `skill_manifest`，新 Pi Run 注入数据库 Revision；动态内容不改变 Root Policy、Capability Pack 版本或工具审核目录。
- child snapshot 从父快照复制 capability/manifest；existing snapshot 只做结构、digest、租户与配置版本校验。
- `load_marketing_skill` 保留历史兼容路径，同时优先读取 Run manifest，审计记录增加 revision。
- 修正 0045 基线的标准契约映射（`insight_board_v1`、`strategy_advice_v1`）并把基线时间写为真实 UTC `datetime`，避免 MySQL 将 `now()` 表达式当作字符串。

### 验证结果

## Task 4：Pi Gateway 原生 Skill 目录物化与显式加载

### 背景与目标

把后端签名并校验过的 Run Skill manifest 变成当前 worker 专属的原生 `SKILL.md` 目录，关闭 Pi SDK 的用户级、项目级和 cwd 自动发现，确保坏快照在模型或 MCP 外发前稳定失败。

### 主要改动

- 新增 `pi-gateway/src/skill-snapshot.ts`：校验名称、revision、内容 digest、大小、重复项和未知文件；在 `.skill-snapshot.tmp-*` 中以 0700/0600 权限写入，fsync 后原子 rename 到当前 Run 的 `.skill-snapshot`，拒绝 symlink、路径穿越和重复物化。
- 扩展 Gateway runtime snapshot 协议和 claim 映射：逐项核对 manifest 与 capability pack 的 revision、digest、正文、required tools、artifact contract，并在 worker spawn 前拒绝内容漂移、超限或 manifest digest 错误。
- `createProductionResourceLoader` 固定 `noSkills/noContextFiles/noPromptTemplates/noThemes`，只允许当前 Run 根目录下的显式快照路径；Root Policy 仍由受控 system prompt 注入，旧 `load_marketing_skill` 兼容路径未删除。
- `createProductionPiSession` 将快照物化置于 MCP 配置、readiness、模型 registry 与 SDK session 创建之前；失败时不会启动 readiness、模型或 MCP。

### 验证结果

- RED 阶段先确认 `skill-snapshot` 模块不存在；GREEN 阶段定向 Vitest：5 个文件、39 个测试通过。
- `npm run typecheck` 通过。
- 新增覆盖：显式快照可加载、自动发现关闭、权限 0700/0600、digest/路径/symlink/未知文件失败、capability 元数据漂移失败、快照损坏时 session 启动前失败。

### 遗留事项

- 管理 UI、通用 `analysis_report_v1`/`workbook_v1` 和生产 Skill 文案迁移尚未开始；真实模型、DataTap、钱包、生产数据库和 Web UAT 仍按计划不执行。
