### 主要改动

**阻断 1 — 同用户跨 Session 已发布报告可引用**

`AgentArtifact.session_id == session_id` 条件，保留 user_id + status=published。
设计 §5.4 / §0 数据隔离确认「跨 Session 可复用当前用户的已发布 Artifact」；草稿、
失败产物与其他用户数据仍 404。测试 `test_unpublished_or_cross_session_version_reference_is_404`
拆分为「草稿/不存在 → 404」与新增「跨 Session 已发布 → 201」两条。

**阻断 2 — Retry 继承原 Run 输入引用**
`router.py` `retry_run`：原实现只冻结「本 Run 产出」的 available Evidence 与 published
Version，丢失原 Run 的输入引用（父 Run / 用户引用 Version / 上游冻结 Evidence），
导致重试重新查 MCP 或结果漂移。修复：合并原 `prompt_snapshot_json` 的
`parent_run_id` / `evidence_ids` / `artifact_version_ids` 到 retry 快照，再并入产出
引用，去重保序。测试 `test_retry_creates_new_run_without_reopening_failed_run` 断言
输入引用继承。

**阻断 3 — 发布不存在 Draft 等失败持久化并参与终态聚合**
发布引用失败（Draft 不存在 / revision 缺失 / 他人持有）原先只返回 failed 结果、
不落 `ArtifactPublishAttempt`，导致 complete 时聚合看不到失败项、Run 被错误标记
completed。修复：
- `backend/app/agent_artifacts/publishing.py`：`_record_rejection` 把引用失败落为
  failed Attempt（幂等键 `reject:{run_id}:{sha256(draft_id)}` 命名空间与 publish/
  abandon 隔离；`artifact_id`/`draft_revision_id` 为 NULL；`validation_json` 存
  `rejected_draft_id` 供聚合标识）。
- `backend/app/agent_artifacts/models.py` + `migrations/versions/0030_direct_publish_runtime.py`：
  `ArtifactPublishAttempt.artifact_id` / `draft_revision_id` 改 nullable。
- `backend/app/agent_runtime/engine.py` `_publish_outcome_artifact_ids`：`artifact_id`
  为 NULL 的失败项用 `validation_json.rejected_draft_id` 标识，避免 sorted(None) 崩溃，
  并让失败项进入 `failed`/`completed_with_warnings` 终态聚合。
  引擎测试 `test_publish_with_nonexistent_draft_id_fed_back_as_failed_item` 与
  `test_publish_with_foreign_draft_id_fed_back_as_artifact_busy` 断言由 `COMPLETED`
  改为 `FAILED`（零发布成功 + 有失败项 → ALL_ARTIFACTS_FAILED），并断言拒绝记录落库。

## Gate A 三轮代码审查修复（1 Critical + 1 Important + 2 Minor）

### 背景与目标

codex 三轮审查：1 项 Critical——幂等重放发生在 owner/归属校验之前，任意其他 Run 只要
获得一个 Draft ID 就能复用原 Run 的 published（返回外部 artifact_id/version，引擎还写
外部 artifact.published 事件）或 validation_failed（返回原错误快照，Pydantic 错误可能含
非法输入值）Attempt，两条路径都绕过 foreign Draft not_found，违反用户/Session 隔离。
1 项 Important——终态聚合把真实 artifact_id 与 rejected_draft_id 放同一无命名空间
字符串集合，模型把已成功发布的 artifact_id 误当 draft_id 提交时失败项会被错误消除。
2 项 Minor——router 注释与无用参数、测试名残留 artifact_busy。

### 主要改动

**Critical — 幂等重放先过归属校验（publishing.py）**
`_publish_one` 幂等重放从「先于 owner 校验」改为「仅本 Run 的 Attempt 可重放」：
- `attempt.run_id == run_id` 时才返回已存 published/validation_failed 结果（本 Run
  崩溃恢复/重试的合法幂等路径不受影响）；
- 他人 Run 的 Attempt（published/validation_failed/validating/failed 任一）一律落入
  durable `draft_not_found` 拒绝——published 不泄漏外部 Artifact 身份、validation_failed
  不泄漏原错误快照，与「foreign draft 统一 not_found」一致；
- 新增防御分支：Attempt 属他人 Run 但 owner 已落本 Run（异常状态）也不得重置/复用，
  统一 not_found。

**Critical 测试（test_direct_publish.py + test_engine.py）**
- 服务层新增 3 例：已发布 Draft 被同用户其他 Run 重放 → not_found、不返回
  artifact_id/version、拒绝记录不保存外部身份；已发布 Draft 被跨用户 Run 重放 →
  not_found；validation_failed Draft 被其他 Run 重放 → not_found、不返回原错误快照。
- 引擎层新增 1 例：run_a 发布成功 → run_b（同 session）重放同一 draft_id → 只回喂
  draft_not_found、run_b 事件流不含任何 artifact.published（外部 Artifact 不进入
  本 Run 事件流），run_b 终态 ALL_ARTIFACTS_FAILED。

**Important — 终态聚合键带域（engine.py）**
`_publish_outcome_artifact_ids` 聚合键从裸字符串改为显式域 tuple：真实 Artifact →
`("artifact", id)`、拒绝记录 → `("rejected_draft", draft_id)`。模型把已发布 artifact_id
误当 draft_id 提交时，拒绝项与 published 项同 ID 但不同域，`failed - published` 不再
错误消除失败项 → Run 保持 completed_with_warnings 而非错误 completed。新增引擎回归测试
`test_publish_artifact_id_confused_as_draft_id_keeps_warning`；既有混合测试断言同步改为
带域形状（`["rejected_draft", id]`）。

**Minor — 注释/签名/测试名清理**
- `router.py`：`_validate_artifact_version_ids` 移除已无用的 `session_id` 参数；
  messages 端点引用校验注释改「Artifact Version 属本用户且已发布（跨 Session 可复用）」，
  与实现一致。
- `test_engine.py`：`test_publish_with_foreign_draft_id_fed_back_as_artifact_busy` 改名
  `test_publish_with_foreign_draft_id_fed_back_as_not_found`，docstring 同步。

### 验证结果

unmapped_fields 仍可巨大（复现 403295 字符）；read_tool_result 固定字段超限时

### 主要改动

**P1 硬预算机制** — `backend/app/agent_runtime/evidence.py` + `tools/history.py`
- evidence.py 新增可复用结构化预算原语：`model_response_size`（统一序列化测量）、
  `fit_dict_by_chars`/`fit_list_by_chars`（按字符预算保留部分条目，返回截断状态）；
- `build_model_evidence_view` 重写降级链：preview/field_mapping/unmapped_fields
  共同参与 50KB 预算 → 先递归裁剪，仍超则 preview 改截断哨兵，再按剩余预算保留
  诊断部分内容，必要时清空诊断（truncated=true 明确裁剪）；**始终保留全部 9 个
  固定键**，任何输出都能 json.loads()；

  返回结构化 `invalid_arguments`，不再原样回显；
- search_evidence：固定字段+matches+每个 view 共同参与总预算；完整 view 放不下

  模型仍可 read_tool_result；最终序列化超预算时从末尾剔除 match；

  逻辑保留。

**P2 XLSX 窄表迭代宽度** — `backend/app/agent_runtime/uploads.py`
- `effective_max_col = min(max(sheet.max_column or 1, 1), _MAX_XLSX_COLUMNS)`，

- max_column > 1000 仍立即拒绝、max_row > max_rows+1 仍立即拒绝；dimension 缺失
  退化为 1 列保持有界（row r 极大不无限迭代）。

## Gate B 最终阻断（search_evidence keyset 分页 + XLSX 坐标预检）

### 背景与目标

Codex 最终复审剩余两个阻断：① search_evidence 只查最新 500 条（SQL LIMIT 500 +
Python 匹配），第 501 条之后的 Evidence 永远无法搜索，无 cursor；② XLSX 用
`sheet.max_column`（read_only 下来自可伪造/可缺失的 `<dimension>`）确定宽度，导致
dimension 缺失或伪造为 A1:A2 时真实 B 列被静默删除。核心细节：搜索游标必须按
"实际消费的源 Evidence" 推进，不能因响应预算跳过未返回的 match。

### 主要改动

**P1 search_evidence keyset 分页** — `backend/app/agent_runtime/tools/history.py`
- `SearchEvidenceArgs.cursor`（max_length=200，受控 base64(JSON {t, i}) 格式），
  无法解析/超长返回结构化 `invalid_arguments`，不抛 500；
- 扫描保持 `collected_at DESC, id DESC`，keyset 条件
  `collected_at < t OR (collected_at == t AND id < id)`，固定扫描窗口 500+1
  （第 501 条仅探测后面是否有数据，绝不一次加载整个 Session）；
- 移除误导性全局 `total_matches`，新契约：
  `query / scanned_count / returned_matches / next_cursor / has_more /
  view_truncated / truncated / matches`；`truncated = has_more || view_truncated`；
- cursor 按实际消费的源 Evidence 推进：响应预算连最小 stub 都放不下时**不消费**
  该 Evidence，下一页重新出现（绝不跳过未返回 match）；
- 完整 view 放不下退回最小 match：`evidence_id/source_type/source_name/run_id/
  collected_at/view_omitted=true`，模型仍可 read_tool_result；
- 每页 `safe_summary <= 50_000`（固定字段占位最保守测量 + 逐项预算校验）；
- 用户/Session 隔离不变，伪造 cursor 只得到 invalid_arguments。

**P2 XLSX worksheet 坐标预检** — `backend/app/agent_runtime/uploads.py`
- 新增 `WorksheetBounds(physical_rows, max_row, max_column)` dataclass 与三个小函数：
  `_resolve_active_worksheet_path`（openpyxl `_worksheet_path`，校验存在且属于
  xl/worksheets/）、`_scan_worksheet_coordinates`（`zipfile.open` + `iterparse`
  流式扫描 row r / cell r，禁止 zf.read 整包加载，物理行数超限提前中止）、
  `_validate_worksheet_bounds`（physical_rows/max_row > max_rows+1 →
  worksheet_dimensions_exceeded；max_column > 1000 → worksheet_columns_exceeded）；
- XML ParseError 与非法 row/cell 坐标 → `invalid_worksheet_coordinate`（受控错误）；
- dimension 快速拒绝保留，但解析宽度改为 `effective_max_col =
  max(actual_max_column, 1)`（≤ 1000）：dimension 缺失/伪造变小不再丢列，
  dimension 比实际大时按实际坐标迭代避免空列；
- `iter_rows(max_col=effective_max_col, max_row=max_rows+1)`。

## Gate B 复审补充（cell 行号校验 / 省略 c@r 隐式列号 / cursor 严格解码）

### 背景与目标

Codex 复审发现三个问题：① `_column_index_from_ref` 只解析列号忽略行号，A1048576
被接受；② 合法省略 `c@r` 且无 `<dimension>` 的两列表格 B 列被静默删除；③ cursor
解码非严格（追加 !! 仍能解析）。

### 主要改动

**uploads.py**
- `_column_index_from_ref` 改为返回 `(column, row)`，严格格式 `[A-Za-z]+[1-9]\d*`
  （A0/A01/B2X/缺行列 → `invalid_worksheet_coordinate`）；
- `_scan_worksheet_coordinates` 把 cell 引用中的行号并入最大行坐标（A1048576 →
  `worksheet_dimensions_exceeded`）；row r 同样用 `[1-9]\d*` 严格校验（r="0" →
  `invalid_worksheet_coordinate`）；
- 省略 `c@r` 的合法单元格按当前 row 内顺序推导隐式列号，不再忽略（无 dimension
  两列表格 B 列保留）。

**history.py**
- `_decode_search_cursor` 严格解码：`base64.b64decode(validate=True)` 拒绝附加
  字符（!! 等）→ JSON 只允许 t/i 两键 → t 必须无时区 ISO 时间、i 非空 →
  **重新编码必须与输入完全一致**（拒绝填充/别名/附加字节变体）。

### 验证结果
- 聚焦测试：241 passed；全量 pytest：1374 passed, 12 skipped；Ruff 通过；
  Alembic head 单一 `0034_dispatch_count`；brand_report cols=6 rows=24；
  A1048576 → worksheet_dimensions_exceeded；row0 → invalid_worksheet_coordinate。
