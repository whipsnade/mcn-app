### 主要改动

**阻断 1 — 同用户跨 Session 已发布报告可引用**

`AgentArtifact.session_id == session_id` 条件，保留 user_id + status=published。
设计 §5.4 / §0 数据隔离确认「跨 Session 可复用当前用户的已发布 Artifact」；草稿、
失败产物与其他用户数据仍 404。测试 `test_unpublished_or_cross_session_version_reference_is_404`
拆分为「草稿/不存在 → 404」与新增「跨 Session 已发布 → 201」两条。

**阻断 2 — Retry 继承原 Run 输入引用**
`router.py` `retry_run`：原实现只冻结「本 Run 产出」的 available Evidence 与 published
Version，丢失原 Run 的输入引用（父 Run / 用户引用 Version / 上游冻结 Evidence），
导致重试重新查 MCP 或结果漂移。修复：合并原 `prompt_snapshot_json` 的
`parent_run_id` / `evidence_ids` / `artifact_version_ids` 到 retry 快照，再并入产出
引用，去重保序。测试 `test_retry_creates_new_run_without_reopening_failed_run` 断言
输入引用继承。

**阻断 3 — 发布不存在 Draft 等失败持久化并参与终态聚合**
发布引用失败（Draft 不存在 / revision 缺失 / 他人持有）原先只返回 failed 结果、
不落 `ArtifactPublishAttempt`，导致 complete 时聚合看不到失败项、Run 被错误标记
completed。修复：
- `backend/app/agent_artifacts/publishing.py`：`_record_rejection` 把引用失败落为
  failed Attempt（幂等键 `reject:{run_id}:{sha256(draft_id)}` 命名空间与 publish/
  abandon 隔离；`artifact_id`/`draft_revision_id` 为 NULL；`validation_json` 存
  `rejected_draft_id` 供聚合标识）。
- `backend/app/agent_artifacts/models.py` + `migrations/versions/0030_direct_publish_runtime.py`：
  `ArtifactPublishAttempt.artifact_id` / `draft_revision_id` 改 nullable。
- `backend/app/agent_runtime/engine.py` `_publish_outcome_artifact_ids`：`artifact_id`
  为 NULL 的失败项用 `validation_json.rejected_draft_id` 标识，避免 sorted(None) 崩溃，
  并让失败项进入 `failed`/`completed_with_warnings` 终态聚合。
  引擎测试 `test_publish_with_nonexistent_draft_id_fed_back_as_failed_item` 与
  `test_publish_with_foreign_draft_id_fed_back_as_artifact_busy` 断言由 `COMPLETED`
  改为 `FAILED`（零发布成功 + 有失败项 → ALL_ARTIFACTS_FAILED），并断言拒绝记录落库。

## Gate A 三轮代码审查修复（1 Critical + 1 Important + 2 Minor）

### 背景与目标

codex 三轮审查：1 项 Critical——幂等重放发生在 owner/归属校验之前，任意其他 Run 只要
获得一个 Draft ID 就能复用原 Run 的 published（返回外部 artifact_id/version，引擎还写
外部 artifact.published 事件）或 validation_failed（返回原错误快照，Pydantic 错误可能含
非法输入值）Attempt，两条路径都绕过 foreign Draft not_found，违反用户/Session 隔离。
1 项 Important——终态聚合把真实 artifact_id 与 rejected_draft_id 放同一无命名空间
字符串集合，模型把已成功发布的 artifact_id 误当 draft_id 提交时失败项会被错误消除。
2 项 Minor——router 注释与无用参数、测试名残留 artifact_busy。

### 主要改动

**Critical — 幂等重放先过归属校验（publishing.py）**
`_publish_one` 幂等重放从「先于 owner 校验」改为「仅本 Run 的 Attempt 可重放」：
- `attempt.run_id == run_id` 时才返回已存 published/validation_failed 结果（本 Run
  崩溃恢复/重试的合法幂等路径不受影响）；
- 他人 Run 的 Attempt（published/validation_failed/validating/failed 任一）一律落入
  durable `draft_not_found` 拒绝——published 不泄漏外部 Artifact 身份、validation_failed
  不泄漏原错误快照，与「foreign draft 统一 not_found」一致；
- 新增防御分支：Attempt 属他人 Run 但 owner 已落本 Run（异常状态）也不得重置/复用，
  统一 not_found。

**Critical 测试（test_direct_publish.py + test_engine.py）**
- 服务层新增 3 例：已发布 Draft 被同用户其他 Run 重放 → not_found、不返回
  artifact_id/version、拒绝记录不保存外部身份；已发布 Draft 被跨用户 Run 重放 →
  not_found；validation_failed Draft 被其他 Run 重放 → not_found、不返回原错误快照。
- 引擎层新增 1 例：run_a 发布成功 → run_b（同 session）重放同一 draft_id → 只回喂
  draft_not_found、run_b 事件流不含任何 artifact.published（外部 Artifact 不进入
  本 Run 事件流），run_b 终态 ALL_ARTIFACTS_FAILED。

**Important — 终态聚合键带域（engine.py）**
`_publish_outcome_artifact_ids` 聚合键从裸字符串改为显式域 tuple：真实 Artifact →
`("artifact", id)`、拒绝记录 → `("rejected_draft", draft_id)`。模型把已发布 artifact_id
误当 draft_id 提交时，拒绝项与 published 项同 ID 但不同域，`failed - published` 不再
错误消除失败项 → Run 保持 completed_with_warnings 而非错误 completed。新增引擎回归测试
`test_publish_artifact_id_confused_as_draft_id_keeps_warning`；既有混合测试断言同步改为
带域形状（`["rejected_draft", id]`）。

**Minor — 注释/签名/测试名清理**
- `router.py`：`_validate_artifact_version_ids` 移除已无用的 `session_id` 参数；
  messages 端点引用校验注释改「Artifact Version 属本用户且已发布（跨 Session 可复用）」，
  与实现一致。
- `test_engine.py`：`test_publish_with_foreign_draft_id_fed_back_as_artifact_busy` 改名
  `test_publish_with_foreign_draft_id_fed_back_as_not_found`，docstring 同步。

### 验证结果

## Gate B 第三轮审核修复（P0 账务状态机 + P1 安全/恢复 + P2 契约，0999cd0）

### P0: dispatch retry 积分幂等状态机
- **根因**：`AgentMcpAccounting` 的 reserve/settle/release 幂等键不区分 dispatch
  attempt，第二次 dispatch 复用第一次的 `agent-mcp:{logical_call_id}:reserve`，
  被 WalletService 判定已执行 → 未真实预留但 `points_reserved=10` → 第二次
  settle 时 `invalid_reserved_amount`。
- **修复**：`AgentMcpAccounting._key(call, op)` 按 dispatch_count 区分——
  dispatch_count=1 保留旧键兼容账本；dispatch_count>=2 用
  `agent-mcp:{logical_call_id}:dispatch:{dispatch_count}:{op}`。reserve/settle/
  release 三者在同一 attempt 用相同规则。
- **测试**：DNR→retry success（两次派发、钱包 available=初始-10/reserved=0、
  Evidence 生成）；DNR→retry unknown（第二次真实预留、reconcile 可 settle）；
  DNR→retry succeeded_empty（结算不生成 Evidence）；DNR→retry 余额不足（不派发）；
  并发恢复（FOR UPDATE 锁保证单一派发者）；同一 attempt 重复 settle/release 幂等。

### P1: retry Step 归属

- **修复**：prepare() 重试分支在提交 running 前 `existing.step_id = context.step_id`，
  恢复/Evidence/lineage 归属当前实际派发 Step。
- **测试**：`test_p1_retry_updates_step_ownership`。
