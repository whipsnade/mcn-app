# 2026-08-05

## J1：模型决策墙钟 + 流式路径治理

### 背景与目标

代码审核确认的系统性根因（真实 UAT 中决策挂 3 分钟+导致租约心跳丢失）：

1. 所有 Agent 决策被强制走流式——网关即使没有真实用户可见 ThinkingSink
   （Reviewer/Utility/内部 Run）也创建 gated sink，全部决策暴露在流式故障面下。
2. 没有整次模型决策的硬性墙钟——`model_timeout_seconds` 是 httpx 读/写/连接级
   超时，流持续 trickle 时永不触发，一次决策可能长期不返回。
3. 流式故障处理不完整——流结束无 `finish_reason` 直接抛 `ModelStreamInterrupted`
   不重试；`MODEL_TIMEOUT` 标记不可重试。此前三个提交只按异常类型逐个补洞。

目标：一次模型决策必须在有限时间内成功、重试后成功或明确失败，三条路径都有
确定上界；无 sink 决策不走流式。

### 主要改动

- `backend/app/core/config.py`：新增 `model_decision_timeout_seconds`（默认 240，
  `MODEL_DECISION_TIMEOUT_SECONDS`）——单次 create 尝试的整次墙钟（含整个流
  消费），注释说明与 Run 租约（300s、心跳每 lease/3 续租）的关系：决策有上界后
  心跳不再因单决策挂死而丢失，默认值须保持小于租约时长。`.env.example` 同步补
  占位符。
- `backend/app/model/tencent_plan.py`：
  - 适配器新增 `decision_timeout_seconds` 构造参数（`from_settings` 接配置），
    `_decision_deadline()` 用 `asyncio.timeout` 包住**每次 create 尝试**：
    流式路径（`_create_json_stream_with_retry`）包住 create + 整个流消费，
    非流式路径（`_create_with_retry`）包住 create。超时即取消本次尝试，
    按可重试 `MODEL_TIMEOUT` 在 `_max_attempts` 预算内重试，最终失败才抛出
    （预算耗尽的墙钟超时保持 `MODEL_TIMEOUT` 语义，不退化为
    `ModelStreamInterrupted`）。
  - 流式故障收口：流结束无 `finish_reason`（`ModelStreamInterrupted`，连接
    中断类、无外部副作用）在预算内整体重试，预算耗尽才抛；`_map_error` 的
    `MODEL_TIMEOUT` 改 `retryable=True`（受墙钟与 attempts 双重上界约束）。
  - `StructuredResult` 新增 `thinking_text`（`contracts.py`）：适配器在流式与
    非流式路径都从解析结果回填供应商思考（reasoning_content / `<think>`），
    跨修复尝试累积，供无 sink 决策写 Step 审计。
- `backend/app/agent_runtime/model_gateway.py`：只有存在真实用户可见
  ThinkingSink 才传 sink 走流式；Reviewer/Utility/内部 Run（`thinking_sink=None`）
  直接走适配器既有非流式 `complete_json` 路径，不再暴露在流式故障面下。
  thinking 事件语义不变（有真实 sink 才有 thinking.*，无思考不发事件）；
  `_GatedThinkingSink` 保留（真实 sink 场景的事件门控与跨尝试审计累积语义仍
  精确匹配现有行为）。无 sink 决策的思考审计改由 `result.thinking_text` 回填
  （脱敏 + 64 KiB 截断不变）；失败 Step 在无 sink 时不再记录部分思考（无
  可用来源，原有测试无此断言，语义可接受）。
- 测试（TDD，先红后绿）：
  - 新增 `tests/model/test_decision_timeout.py` 6 例——trickle 流触发决策墙钟
    → 重试 → 成功（总耗时 < 5s 有上界）；每次尝试都超时 → 预算耗尽明确失败
    MODEL_TIMEOUT；非流式挂死 create 同样收口；无 finish_reason 预算内重试
    成功/耗尽失败；`_map_error` MODEL_TIMEOUT 可重试。
  - `tests/model/test_structured_stream.py`：无 finish_reason 用例改为「预算内
    重试、耗尽才失败」语义（重试会重放该次尝试的部分思考 delta，与生成中止
    重试一致的取舍）。
  - `tests/agent_runtime/test_model_gateway.py`：无 sink 用例全部切非流式
    fixture（`<think>` 内联思考）；新增 2 例锁定路径选择——无 sink 断言
    `stream=False` 且思考审计经 `thinking_text` 回填、有 sink 断言 `stream=True`
    且 thinking 事件转发。running→completed 快照用例改阻塞式非流式 fake。
  - `tests/agent_runtime/test_engine.py`（2 例真实网关回喂/收口用例）、
    `tests/agent_runtime/test_reviewer.py`、`tests/agent_artifacts/test_review_batch.py`
    的模型 fake 同步切非流式 fixture（Reviewer/Utility 本就 `thinking_sink=None`）。

### 遗留事项

  退避）内必然收口，租约心跳不再因 trickle 流挂死丢失；Reviewer/Utility 决策

## H5：build_insight_draft Builder 收口钻取看板产物交付

### 背景与目标

真实 UAT 取证：开放式钻取连续两轮失败——模型用 `create_draft` 手写
`insight_board_v1` payload，即使有字段级错误回喂（`data.0 block_type 不匹配`、
`metric_grid.metrics 多余字段` 等）也收敛不了（第一轮 7 次失败收尾、第二轮
烧光 50 决策 paused）。五类强类型产物由 Builder 兜底后已全部可交付，
insight_board_v1 是最后一个没有 Builder 的正式产物。本任务按 codex 复审后的
修订规格落地第六个 Builder：模型连数值都不填，只提交板块结构与每个数字的
`value_ref` 引用，工具解析引用复制真实值，Builder 确定性组装。

### 主要改动

- 新增 `backend/app/agent_artifacts/builders/insight.py`：
  - 模型输入契约（全部 `extra="forbid"`）：`ValueRef` 判别联合三来源——
    `evidence{evidence_id, source_path}` / `artifact{artifact_version_id,
    source_path}` / `calculation{tool_call_id, result_path, input_refs≥1}`
    （input_refs 是 derivation 的输入基座，与 kol_selection 评分 derivation
    同一契约）；`BlockSpec` 判别联合 8 型（metric_grid/table/bar_chart/
    line_chart/pie_chart/markdown/timeline/references，判别字段 `type`）——
    metric 值、series 数值、pie 值必须给 value_ref，table 单元格文本直接给
    字符串、数值必须 `{"value_ref": ...}`，裸数字字面值被 Pydantic 字段级
    拒绝。
  - 纯 builder `build_insight_draft`：输入「已取值的 ResolvedBlock +
    数字级 ResolvedLineage」，组装 payload（availability.blocks=complete /
    data_status=complete / limitations=[] / methodology 自动生成；narrative
    缺省按 question 生成兜底），经 `InsightBoardV1` 强校验（narrative
    supporting_paths、scope 多余字段、URL scheme 在此拦截），lineage 路径
    可解析且唯一性自检，输出 `DraftBuildResult`（module="insight"，稳定
    key 走 keys.py 既有 `insight:{parent_version}:{question_hash}` 规则）。
- `backend/app/agent_runtime/tools/builders.py` 新增 `BuildInsightDraftTool`
  （Args：parent_artifact_version_id/question/title/scope/blocks[1-50]/
  narrative 可选）：
  - 父 Version 校验：Version 行只在发布时产生（存在即已发布），不存在或
    跨 Session 一律 `not_found` 不泄漏存在性；payload module 从父 Artifact
    推导（brand→brand、campaign→campaign、其余→kol）。
  - value_ref 解析与取值：evidence/artifact 归属校验 + RFC6901 source_path
    必须可解析；calculation 必须是当前 Session 已 settled 的 internal 调用
    （结果经 step.output_json.safe_summary 持久化），input_refs 逐个校验可
    解析后生成 derivation{tool_call_id, method, input_paths}。
  - 图表数值（series/pie）必须解析为数字、metric/table 必须是标量；任一
    引用失败 fail-fast 为结构化 `draft_build_error`，指明出错板块位置
    （如 `blocks.0.cards.0`），一次回喂全部错误。
  - 数字级 lineage 自动生成：artifact_path 按板块位置构造
    （`/data/{i}/cards/{j}/value`、`/data/{i}/rows/{r}/{c}`、
    `/data/{i}/series/{s}/values/{v}`、`/data/{i}/slices/{s}/value`）。
  - 输出契约不变：只回 artifact_id/draft_id/revision_id/schema_version +
    受限摘要，不回灌 payload；同身份重调（Reviewer revise 后）追加新
    Revision。
- 护栏收口（`tools/artifacts.py`）：`insight_board_v1` 加入
  `_TYPED_BUILDER_BY_SCHEMA`，create_draft/update_draft 裸写 insight 一律
  `typed_artifact_requires_builder` 回指 build_insight_draft——至此六类强
  类型全部禁止直写，create/update_draft 不再承接任何强类型 payload。
- 装配与指引：`tools/factory.py` 注册进 ARTIFACT_TOOLS（与五个既有 Builder
  同层）；`engine.py` 的 `_DRAFT_EVENT_BY_TOOL` 补
  `build_insight_draft → artifact.draft.created`；`prompts.py` 主 Analyst
  指引改「六类一律走 Builder」，create/update_draft 不允许直写任何强类型。
- 测试（TDD，先红后绿）：
  - 新增 `tests/agent_artifacts/test_insight_builder.py` 9 例——8 型 Block
    全覆盖且 emit refs 恰好等于必选 numeric 指针集、narrative 兜底/透传/
    非法拒绝、lineage 路径越界与重复拒绝、scope 多余字段拒绝、非法 module
    与空 blocks 拒绝。
  - 新增 `tests/agent_runtime/tools/test_insight_builder.py` 11 例——端到端
    （三来源取值正确、lineage 自动生成、parent 绑定、稳定 key、输出不回灌
    payload）、revise 重调追加 Revision、父 Version 不存在/跨 Session
    not_found、source_path 不可解析字段级回喂、跨 Session evidence 拒绝、
    第 9 种 block 类型拒绝、模型常见错误（多余字段/双包嵌套/裸数字字面值）
    字段级回喂、计算调用未 settled/非 internal 拒绝、字符串充当图表数值
    拒绝、narrative supporting_paths 校验。
  - 既有测试随护栏收口更新：`tools/test_artifacts.py` 两个「insight 允许
    直写」用例反转为护栏拒绝（_TYPED_CASES 增 insight 行）；
    `test_engine.py` 两个 Draft 事件用例改为 build_insight_draft 成功发
    artifact.draft.created / update_draft 直写被拦不发事件；
    `test_validation.py` 两个结构化回喂用例改用未注册 module 继续覆盖
    ArtifactPayloadInvalid 路径；`test_kol_analysis_builder.py` 的
    create/update 持久化用例改为 registry 级护栏断言；
    `tools/test_factory.py` kol_detail profile 可见集与
    `tools/test_builders.py` BUILDER_TOOL_NAMES 同步增 build_insight_draft。

### 偏差决策（相对任务书）

- 「部分引用失败 → restricted + limitation」改为 fail-fast：板块数值字段
  不可空（series 为 float 数组），无法像强类型报告那样用 null + limitation
  表达缺失，静默丢板块又会打断 narrative supporting_paths；统一为
  draft_build_error 一次回喂全部失败引用位置，模型修正后重试（与「Evidence

  `input_refs≥1`：LineageRef 契约要求 sources 至少 1 条且 derivation
  input_paths 必须能在来源 payload 中解析，无输入基座的计算结果无法通过
  发布边界的 lineage 冻结。

## 营销报告主线与统一 Runtime 修订设计

### 背景与目标

用户重新确认系统面向品牌营销人员的完整业务旅程：单品牌社媒调研、达人圈选、
线下投放、活动效果评估。正式交付以品牌/活动/达人 Excel 为主线，同时生成右侧
BI，并支持多轮澄清、历史钻取、用户投放资料和 DataTap 故障恢复。

本次先完成需求与架构设计，不修改业务代码。设计实施基线为
`codex/agent-runtime@31312e3`，不重建第二套 Session/Run/Evidence/Artifact 运行时。

### 主要决策

- 新增设计：
  `docs/superpowers/specs/2026-08-05-marketing-report-runtime-revision-design.md`。
- 移除正式产物最后的模型 Reviewer：动作协议从 `submit_review` 改为
  `publish_artifacts`，Builder 后只执行确定性 Schema、lineage、缺失治理、引用路径、
  叙事数字一致性和归属检查；Reviewer 表首期只停写不删除。
- 每条用户消息继续创建独立 Run；澄清回答和钻取补齐 `parent_run_id`；一条消息可
  生成多个 Artifact，各自产生独立发布结果，Run 聚合为 completed /
  completed_with_warnings / failed。
- 品牌报告沿用 `brand_report_v3`，按用户模板固定 8 个章节；活动沿用
  `campaign_report_v2` 并新增 9 Sheet Excel，满足内部成本与转化数据条件时动态增加
  ROI Sheet；达人沿用 `kol_selection_v3` Artifact 体系但评分升级为
  `kol_value_score_v3`。

## Gate A：直接发布与 Run 生命周期

### 背景与目标

删除新执行链中的模型 Reviewer，以确定性发布替代；补齐独立 Artifact 结果、Run 父子
关系和结构化 Scope 记忆。Builder 继续生成不可变 Draft Revision，新的
`ArtifactPublicationService` 对 Revision 做确定性校验并逐项发布 Version；`publish_artifacts`
是非终态模型动作，`abandon_draft` 是受控内部工具；Run 只有在所有归属 Draft 已发布或
失败后才能 `complete`。对应实施计划
`docs/superpowers/plans/2026-08-05-direct-publish-run-lifecycle.md` Tasks 1–6。

### 主要改动（Tasks 1–5）

- **Task 1 — 0030 迁移与模型**：新增 `backend/migrations/versions/0030_direct_publish_runtime.py`，
  建 `artifact_publish_attempts` 表（`idempotency_key` 唯一幂等；状态
  `validating/published/validation_failed/failed`；FK→runs/artifacts/draft revisions/versions），
  给 `agent_artifact_versions` 加 nullable JSON `validation_json`（新 Version `review_json=None`），
  重建 `memory_entries` 类型 Check Constraint 加入 `confirmed_scope`；downgrade 只移除本迁移
  对象，不碰 Review 表。`agent_artifacts/models.py` 新增 `ArtifactPublishAttempt` ORM；
  `agent_runtime/models.py` `MemoryEntry` 接受 `confirmed_scope`。
- **Task 2 — 动作协议与 Prompt**：`schemas.py` 删除 `submit_review`，新增
  `PublishArtifacts` 动作（`artifact_draft_ids` 非空唯一、`summary`），`FOUR_ACTIONS`
  定为 `{ask_user, call_tool, publish_artifacts, complete}`；`prompts.py`/`profiles.py`
  改写 Session Analyst 指引：六类强类型仍必须 Builder，`publish_artifacts` 非终态，发布
  失败按结构化问题修订或调用 `abandon_draft`，`complete` 前不得留下活动 Draft；删除
  Reviewer 指引，`artifact_reviewer_v1` Profile 注册保留供历史代码导入但不进新 Runtime wiring。
- **Task 3 — 发布服务与放弃工具**：新增 `backend/app/agent_artifacts/publishing.py`
  `ArtifactPublicationService.publish(run_id, draft_ids, worker_id) -> tuple[PublishItemResult, ...]`，
  逐 Artifact 独立事务发布、同一 Draft Revision 幂等（`idempotency_key`）不重复 Version、
  一个失败不回滚其他成功项；校验快照写入 `ArtifactPublishAttempt.validation_json` 和
  Version `validation_json`。把 `ArtifactService.publish_batch` 的 Version 冻结/lineage
  snapshot/事件序列抽成单 Draft helper。`tools/artifacts.py` 新增 `AbandonDraftTool`：
  只允许 owner Run 把未发布 Draft 置 failed、写一条 `failed` attempt 保存结构化原因、
  发 `artifact.failed` 事件，不为 Draft 表临时增加错误列。
- **Task 4 — 引擎接线与终态聚合**：`engine.py` 删除新路径对 `ReviewerService` 的构造
  依赖；`publish_artifacts` 调用发布服务、发逐项 `artifact.published` + 汇总
  `artifact.publish.completed` 事件后继续 while loop；`complete` 查询当前 Run Draft
  状态，有活动 Draft 时回喂 `ACTIVE_DRAFTS_REMAIN`；终态按发布/失败项聚合为
  `completed`/`completed_with_warnings`/`failed`，零发布产物收口 `failed`（收口补丁）。
  历史 `reviewing` Run 在恢复扫描收口 `failed`（`LEGACY_REVIEWING_UNSUPPORTED`），保留
  Draft、不启动 Reviewer。`state.py`/`executor.py`/`main.py` 把 `completed_with_warnings`
  纳入终态集合、租约、取消、暂停和 executor 扫描。
- **Task 5 — 父 Run、Artifact 引用与 confirmed_scope**：`router.py` `AgentMessageCreate`
  新增 `parent_run_id`、`artifact_version_ids`（≤10），建 Run 前校验 parent Run 和
  Version 归属、把引用快照写入 `prompt_snapshot_json`；新增 `POST /agent/runs/{id}/retry`
  只接受 failed/paused Run、创建新 user-visible Child Run、冻结有效 Evidence/Artifact 引用、
  不修改或重开原 Run。`memory.py`/`context.py` 新增内部工具 `remember_scope`：
  supersede 同 domain+field 旧 active memory，Context Builder 只注入未 supersede 条目。
  `tools/history.py` 支持跨 Session 已发布 Artifact 引用与归属校验。补丁限制 retry 仅
  接受 Session Analyst Run。
