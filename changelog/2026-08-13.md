### 主要改动

- Run 创建按已审核 capability pack/profile 解析 required artifact contract，并将 profile、pack version、manifest digest 固化到不可变 RuntimeSnapshot；terminal、Recovery、ACK-loss 和 force-complete 只读取该快照。
- Gateway/adapter 与后端共同执行严格 `mcp_result_v1` 判别联合：`available` 必须是非空 `structuredContent`，`empty`/`unavailable` 禁止结构化载荷；仅允许唯一且整体合法 JSON 的审核 MCP text block，普通文本、resource、图片和临时路径不能成为 Evidence。
- 明确 success/empty/unavailable/failure/unknown 的结算语义，持久化 Pi upstream request/logical call id；reconciliation 二次执行 allowlist schema 校验，unknown 不自动释放、不自动扣除。
- 抽出统一 CompletionValidator，覆盖正常 terminal、terminal ACK 丢失 Recovery、force-complete 和恢复重试；required artifact、Publication/Version/lineage、当前 Run 归属及 unresolved MCP 均为服务端门禁。
- 新增跨 Attempt 持久化 LoopGuard（迁移 0044），对稳定 builder 错误和无 Evidence 集合变化的 `search_evidence` 使用固定错误指纹/集合版本/阈值 3，达到阈值后以 `agent_loop_circuit_open` 稳定失败并保留一次解释性 assistant message。
- thinking/message delta 按 4 KiB、32 fragments、50ms 合并；语义边界、worker finally、取消/中止、provider/decision failure、child exit 及 terminal 前均 flush/drain，保留默认有界 Gateway buffer。
- 修正离线 UAT harness 清理 `agent_tool_call_reconciliations` 的错误键列，避免测试基础设施残留影响后续 topology。

### 红灯与根因

- 先用脱敏的真实 adapter 结果形状补充非空 structured result、唯一合法 JSON text、空结果、多个 text、普通文本、UI resource、图片、路径、过大载荷、明确失败和 unknown 的测试；修复前结果包络不完整时无法安全进入后端 Evidence/结算链路。
- completion 负例先覆盖「有 assistant 但无 brand_report_v3」「历史 Version」「running Step/ToolCall」「unknown」「无效 lineage」；修复前 assistant-only terminal 会错误完成 Run。
- builder/search 重复错误、跨 Attempt、delta 高事件量和所有终止边界先补红；修复前无持久化 guard，Gateway 依赖大缓冲吸收洪泛。
- 另发现直接使用具体 output schema 的普通 `AgentMcpTool` 不应被 DataTap service 的 `{result: string}` 包装规则全局误判；最终改为由 canonical envelope 加具体审核 output schema 做最终信任边界，DataTap Pi allowlist 路径仍保留其专用 wrapper 校验。
