失败 Run `3c3e6a2d-f020-453a-aa05-4e7bdb5e58b5` 的已知事实：

### 主要改动

- Run 创建按已审核 capability pack/profile 固化 capability allowlist、pack version、manifest digest 到不可变 RuntimeSnapshot；不再从 Profile、用户文本、模型输出或 Builder 调用推导 required artifact。terminal、Recovery、ACK-loss 和 force-complete 只读取该快照。
- Gateway/adapter 与后端共同执行严格 `mcp_result_v1` 判别联合：`available` 必须是非空 `structuredContent`，`empty`/`unavailable` 禁止结构化载荷；仅允许唯一且整体合法 JSON 的审核 MCP text block，普通文本、resource、图片和临时路径不能成为 Evidence。
- 明确 success/empty/unavailable/failure/unknown 的结算语义，持久化 Pi upstream request/logical call id；reconciliation 二次执行 allowlist schema 校验，unknown 不自动释放、不自动扣除。
- 抽出统一 CompletionValidator，覆盖正常 terminal、terminal ACK 丢失 Recovery、force-complete 和恢复重试；当前 Run 已自主生成产物时严格校验 Publication/Version/lineage 与归属，required artifact 不再是新 Run 的服务端必达门禁，unresolved MCP 仍受平台门禁约束。
- 保留跨 Attempt 持久化 LoopGuard 的错误指纹/Evidence 集合版本/阈值观测，但取消 Builder/Search 业务熔断和强制终态；高层 `max_decisions` 仍是唯一通用决策 fuse。
- thinking/message delta 按 4 KiB、32 fragments、50ms 合并；语义边界、worker finally、取消/中止、provider/decision failure、child exit 及 terminal 前均 flush/drain，保留默认有界 Gateway buffer。
- 修正离线 UAT harness 清理 `agent_tool_call_reconciliations` 的错误键列，避免测试基础设施残留影响后续 topology。

## 架构转向：Pi 透明 MCP 结果与 Artifact Skill（覆盖本文件前述旧方向）

### 背景与目标

用户在本日明确作出新的架构决策：DataTap MCP 是自研、受控的内部服务，Pi 主链路不再承担 Evidence Bridge 的二次解析、归一化、业务 Schema 复核或可信判定。本节覆盖前述同日的 `mcp_result_v1`/Evidence Bridge 实施方向；历史事实保留，旧数据、旧 Evidence 和旧 Run 不改写。本轮仍只做离线开发与验证。

### 主要改动（关键边界）

- 标准 Pi adapter 将 MCP Tool Result 原样交给模型；accounting hook 只观察调用并发送严格的 metadata-only finalize，不读取或替换 `event.content`，不把业务 payload、text/resource/image、临时路径或模型上下文带入 IPC/控制面。
- Gateway 保留 tenant/run/tool 身份、allowlist、secret 隔离、预留、logical_call_id、幂等及 settle/release/unknown 状态；ACK 丢失不改写模型结果、不创建 Attempt 2。unknown 不自动 replay、release 或扣除。
- Run Snapshot 只固化服务端审核 capability pack/profile 形成的候选 `allowed_artifact_contracts`、pack version 与 manifest digest；用户文本、模型输出和 Builder 调用不决定 contract。历史 required 字段只作为旧 Snapshot 兼容读取，Pi worker 不接收也不消费 required contract。
- Artifact Skill 的 `build_artifact_draft` 接收模型自主选择的 `artifact_type`、严格 payload 和可选的当前 Run ToolCall ID；不读取 Evidence。父 Artifact Version 仅允许同一 Session 的已发布 lineage 引用，不复制跨 tenant/session/Run 的 payload。Publication、Version、lineage 与 BI/Excel 同版约束继续有效。
- 统一 `CompletionValidator` 覆盖正常 terminal、ACK-loss Recovery、Recovery 与 force-complete；无 Artifact 可以正常文字完成，Evidence 数量不构成完成门禁；实际发布的 Artifact 仍需满足当前 Run 和 Snapshot allowlist 的完整链路。
