## Gate A 修复：MCP durable-before-send、熔断接线、禁自动重试与 reconciler 接线（A3）

### 背景与目标

- 依据 `docs/superpowers/specs/2026-08-03-agent-runtime-v3-hardening-design.md` §2.1/§5.3，
  修复审核发现的四个发布阻断缺陷（均属阻断条件 #1「重复执行/重复扣费/错误释放」）：
  1. `AgentMcpTool.execute` 把调用行、积分预留、`mark_running` 放在外层事务的 savepoint
     里，进程在「外发后、返回前」崩溃时整体回滚，恢复后模型可能重发同一调用；
  2. 旧服务级熔断（`circuit_scope="service"` 默认）与细粒度熔断两层叠加，且每个
     `AgentMcpTool` 实例自建空熔断器，细粒度熔断在生产永不触发；
  3. DataTap 传输层对 5xx/504（属 result_unknown）自动重发一次，违反「禁止自动重放」；
  4. `app.state.agent_tool_reconciler` 从未接线（admin confirm_success 永远取不回
     payload），且 reconcile 取回的 payload 未经输出 Schema 校验直接落 Evidence。

### 主要改动

- `backend/app/agent_runtime/tools/mcp.py`：新增 `DurableToolCallCoordinator`——
  `prepare()` 用独立 DB Session 单一事务完成 Run/Step 归属校验、logical_call_id
  锁定、调用行插入或复用、10 积分预留、`running`+`started_at` 落库，**commit 之后才
  允许外发**（预留与调用行同事务，消除悬挂预留窗口）；`finalize_success/release/
  unknown` 各自独立事务并带终态守护（已终态幂等跳过，不重复触碰钱包）；reconcile
  系列（`load_call/keep_unknown/confirm_success/confirm_failure`）同样独立事务即时
  提交。`AgentMcpTool.execute` 全部改走协调器；进程取消（`asyncio.CancelledError`）
  且请求可能已发送时按 `result_unknown` 收口后继续抛出。旧 `_db_transaction`
  savepoint 助手删除（无其他调用方）。`db_session` 构造参数保留兼容（A2 装配路径），
  durable 读写一律经 `session_factory`（默认真实 `SessionFactory`）。
- `backend/app/mcp_gateway/datatap.py`：新增构造参数 `retry_policy`
  （`"transient_once"` legacy / `"never"` 默认）。Agent 路径固定 `"never"`：
  504、5xx、协议中断、PossiblySentTimeout 都不自动重发（生产已无 legacy 消费方，
  默认直接收紧；legacy 策略可显式 opt-in）。
- `backend/app/mcp_gateway/service.py`：新增 `get_agent_mcp_transport()`（lru_cache，
  `circuit_scope="none"` + `retry_policy="never"`）。
- `backend/app/agent_runtime/tools/factory.py`（与 A2 签名协调的最小增量）：
  `AgentToolRegistryFactory` 新增可选 `breaker` 参数并传入每个 `AgentMcpTool`；
  默认 `transport_getter` 改为 `get_agent_mcp_transport`。
- `backend/app/main.py`：`create_agent_runtime` 创建进程级共享
  `FineGrainedCircuitBreaker`，engine 工具与恢复工具共用；`create_app` 接线
  `app.state.agent_tool_reconciler = get_agent_mcp_transport().reconcile_tool_call`
  （lifespan 与测试回退路径都设置）。
- `backend/app/agent_runtime/recovery.py`：`RecoveryLoop` 新增
  `migrate_stuck_tool_calls()`——超过 `stuck_seconds`（新配置
  `AGENT_TOOL_CALL_STUCK_SECONDS`，默认 900s，`started_at` 为准，NULL 按 stuck）
  仍处于 running/reserved 的调用，经 `SELECT ... FOR UPDATE` + 状态谓词守护迁移为
  unknown（保留预留，绝不直接释放或重发），`run_once` 同轮完成迁移 + 核对，返回值
  扩展为四元组。
- `backend/app/admin/service.py`：admin confirm_success 取回的 payload 经
  `resolve_allowlist_entry` + `validate_output` 校验通过才写 Evidence，否则退化为
  settle + `result_unavailable`（不伪造 Evidence）。

## Gate A 修复：Run 接管重建上下文、reviewing 恢复、租约心跳、取消语义与 resume 互斥（A4）

### 背景与目标

- 依据 `docs/superpowers/specs/2026-08-03-agent-runtime-v3-hardening-design.md` §5.4/§5.5，
  修复审核发现的五个恢复/并发缺陷：
  1. 接管不重建 Run 内对话上下文（executor `_build_messages` 只注入用户输入），恢复后模型
     看不到本 Run 已完成的工具调用与结果，必然重复调用已 settled 的 MCP 工具 → 重复扣费；
  2. reviewing 状态崩溃不可恢复（可领取扫描只认 queued/running、`claim_lease` 拒绝非
     running）→ Reviewer 复核期间崩溃 Run 永久卡死；
  3. 租约只在决策循环顶续租（300s），单次长迭代（decide/MCP/Reviewer）超时即被误判死亡
     → 双 worker 并发窗口或 Run 以 `run_lease_lost` 误失败；
  4. 取消路径断裂（生产无人调用 `request_cancel`，API 直接 `cancel` 置终态）→
     `run.cancelled` 事件从不发出，decide 期间到达的取消不阻止随后的工具外发与计费；
  5. paused Run resume 不检查同 Session 其他活动主 Run → 双主 Run 并发。

  `evidence_id + 结构化预览`，与正常工具返回形态一致，不回灌 raw payload；failed/unknown
  回放原结构化错误）；崩溃残留的 running Step 按 `agent_tool_calls` 行当前状态构造结果
  回放（settled→success、failed→原错误、其余→unknown 待核对），并作为 `resume_step`

## Gate A 复审修复：统一 Run 终态事件与 artifact SSE 契约（G1）

### 背景与目标

Gate A 复审发现两个跨层契约缺陷：

- **P0 部分失败路径没有终态 SSE**：Reviewer reject（含第 3 次 revise 映射）只发
  `review.rejected` 就把 Run 置 failed，不发 `run.failed`；executor `_finalize_failed`
  异常收口也只改库不发事件。SSE 流不结束、前端 Run 卡停在中间态，违反加固设计
  §5.8「Run 终态事件必须是该 Run 最后一条用户可见 SSE 事件」。既有 reject 测试
  只查数据库状态，所以全绿但契约断裂。
- **P1 Artifact 事件没接入统一 Run SSE**：Draft 创建/更新/发布只写
  `artifact_events` 表，从不发 `artifact.draft.created/updated`、
  `artifact.published` 到 Run 事件流；前端 `agentEvents.ts`/`useAgentWorkspace.ts`
  靠这些事件驱动 `artifactsVersion` 增长刷新右侧 BI 与未读圆点（§15.3）。

目标：所有使 Run 进入终态的路径恰好发一个终态事件且为该 Run 最后一条用户可见
事件；artifact 生命周期事件全量接入统一 Run SSE。

### 主要改动（含关键文件）

- `app/agent_runtime/events.py`：`AgentEventStream` 新增 `append_terminal_once`
  ——终态事件统一出口，同一 Run 已有终态事件时幂等返回 None（全局恰好一个），
  非终态类型抛 `ValueError`。
- `app/agent_runtime/engine.py`：
  - 全部终态出口（complete / approve 发布 / reject / `_fail_run` / 取消）改走
    `append_terminal_once`；reject 分支在 `review.rejected` 后补发 `run.failed`
    （`error_code=review_rejected`）；
  - `_fail_run` 增加稳定 `error_code`：decide 异常 `model_error`、连续无效动作
    `max_invalid_actions`、续租失败 `run_lease_lost`、reviewing 无 Batch
    `review_batch_missing`；`_abort_review` 区分 `review_error`/`publish_error`；
  - Draft 工具成功后在 tool 流程中发 `artifact.draft.created/updated`
    （`_emit_draft_tool_event`；create 复用既有身份 revision>1 时记 updated，
    与 artifact_events 表口径一致）；原子发布成功后为每个 Artifact 发
    `artifact.published`（`_emit_artifact_published`，顺序在
    `message.completed` 之前）；payload 均带
    `artifact_id/module/parent_artifact_id/status`，发布另带 `version`，
    draft 事件 `version` 为 Draft revision 号；kol_detail Run 走同一引擎路径
    自动覆盖。
- `app/agent_runtime/executor.py`：构造函数新增可选 `broker`；`_finalize_failed`
  在本 worker 真实把 Run 置 failed（transition 成功或 force_fail 确认无其他
  活跃持有者）后发 `run.failed`（`error_code=executor_error`）；已终态或租约
  被他人活跃持有（接管方负责，A4 闸门）时不发，事件补发失败不掩盖已落库终态。
- `app/main.py`：executor 注入进程级共享 broker，SSE 订阅即时收到补发事件。
- 前端 `src/state/agentEvents.test.ts`：reducer 分支此前已齐备（核对结论），
  新增 payload 字段（`parent_artifact_id`/`version`）与 `artifactsVersion`
  只在 artifact/review 事件增长的断言。
- 测试（跨层 SSE 断言，不只查库）：
  - `test_engine.py` 新增 10 例——reject / 第 3 次 revise→reject 事件序列以
    `run.failed` 收尾、publish/reviewer/decide 异常与无效上限的 error_code、
    draft.created/updated 在 tool.succeeded 后 message.completed 前、
    artifact.published 顺序与 payload、独立会话在线消费 reject 路径流以
    `run.failed` 收口（新增 `_purge_committed_review_run` 按 FK 依赖序清理
    review/artifact 链与内部子 Run）；
  - `test_executor.py` 新增 4 例——引擎 decide 外崩溃 executor 补发
    `run.failed(executor_error)` 且事件序列以其收尾、引擎已收口后兜底不重复、
    租约被他人活跃持有时兜底不改状态不发事件（A4 闸门回归）、独立会话在线
    消费 executor 崩溃路径流收口；
  - `test_events.py` 新增 `append_terminal_once` 幂等单测；
  - `test_kol_detail.py` 新增 kol_detail Run 产物事件（draft.created →
    published → run.completed）断言。
