## 品牌分析报告导出与 BI 重构（brand_report_v2）

- 设计 spec：`docs/superpowers/specs/2026-07-30-brand-report-export-and-bi-design.md`；
  实施计划：`docs/superpowers/plans/2026-07-30-brand-report-export-and-bi.md`。
  在 `feat/brand-report-export-bi` 分支按 subagent-driven-development 执行
  （每 Task 实现 + spec 合规评审 + 代码质量评审两段把关），共 10 个 Task。
- 目标：品牌分析报告从通用 Block 升级为结构化快照 `brand_report_v2`，
  提供零积分 Excel 导出，右侧品牌分析 BI 改为与 Excel 模板章节一一对应的
  章节式渲染；旧版报告不回填、走通用 Block 降级。

### 主要改动

- 存储：`analysis_reports` 加 `payload_json`/`template_version`（迁移 0026，
  旧行 NULL）；列表 API 不返回大载荷，仅详情返回。
- 采集：`GoalParams.comparison_mode`（mom 默认/mom_yoy），planner prompt
  升 v3（brand_analysis 必落该字段）；`brand_loop_v1` 升 v2——对比期阶段
  （当期→对比期→其余维度；mom 查上一等长周期、mom_yoy 加查上一年同期，
  2/29→2/28；无 period 不猜对比窗）+ evidence_goal 期别前缀
  `current:/mom:/yoy:`。注意：默认 mom 使品牌分析多一组同口径 MCP 调用
  （每次 10 积分），总量接近翻倍，属设计预期。
- 构建：`run_brand_analysis` 原地演进 v2——`brand_assembler.py`（确定性归一：
  期别前缀优先 + arguments 日期兜底、top_posts≤15/regions≤20 截断、
  data_as_of、对比降级状态机 not_requested/restricted、data_status 聚合、
  无当期 overview 证据抛 no_evidence_collected）→ `brand_narrative.py`
  （输入仅 scope/query_spec/data/availability，叙事失败=构建失败）→
  兼容 ReportDocument（旧 BI 消费方行为不变）一次落库。
- 导出：`GET /sessions/{id}/reports/{report_id}/export`——归属/类型校验
  统一 404 不泄漏存在性；`brand_exporter.py` 以去样例模板
  `reporting/templates/brand_report_v2.xlsx`（脚本
  `scripts/build_brand_report_template.py` 从根目录 brand_report.xlsx 生成，
  产物入库）渲染 8 Sheet，图表删除重建、空章节保留列头+受限说明、
  文件名清洗；不调模型/MCP/积分。
- 前端：contracts.ts 类型镜像后端 payload；`BrandReportView` 章节式 BI
  （8 章节锚点导航、受限徽标+原因、趋势 unavailable 不渲染图表、热帖平台
  切换/展开/「未提供」、方法论折叠、AI 结论与建议置后）；
  `isBrandReportPayload` 形状守卫，不过则降级旧 Block +「该历史版本不支持
  模板导出」；导出按钮随版本切换联动。
- 旧 `brand_analysis` 记录不迁移；`brand_analysis_v1` prompt 不再使用
  （保留未清理）。analysis-retry 复用 v2 构建器，新增 no_evidence_collected
  →409 映射。

## 蔚来品牌报告 no_evidence_collected 误报修复

- 现象：合并后首个真实品牌任务（蔚来）goal 落 completed_with_warnings，
  brand_report artifact failed/no_evidence_collected——但轨迹里 overview 证据
  明明 settled（声量 156,438）。
- 根因（终审 F3 预警命中）：真实 overview 输出是**无平台键的单条聚合行**
  （多数据源合并统计），`_canon_platform` 归为 "all"，被防双计逻辑全部跳过
  → 概览门禁误报无证据。另发现情感字段别名缺「正面声量数」等带「数」变体。
- 修复：`_aggregate_overview` 改为「具名平台行与聚合行并存时跳过聚合行
  （防双计），仅存聚合行时使用聚合行（归 all 平台）」；`_POSITIVE/NEUTRAL/
  NEGATIVE_KEYS` 补「正面声量数/中性声量数/负面声量数」别名。
- 验证：新增用例（聚合行独占时使用、并存时跳过）+ 用蔚来真实 plan_json
  跑通组装（partial：overview 缺 exposure；mom restricted/no_data——模型未
  按 prompt 查对比期；yoy not_requested）；全量 927 passed。
- 蔚来会话可用 `POST /sessions/{id}/analysis-retry` 重新生成 v2 报告。
- 遗留：overview 聚合行内联了环比/同比值（声量的环比值等），当前组装器
  不消费（对比期靠独立 mom/yoy 查询）；模型未遵守 brand_loop v2 的对比期
  阶段（5 次调用即 finish），prompt 遵从度待观察。
