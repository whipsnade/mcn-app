# B0 Gate 加固 R2

## 背景与目标

复审发现 Task 6 的 hard checks 仍可被 Artifact 自报布尔值绕过，Task 7 回放只验证预制
结果而没有执行 B0 数据链路，Task 5 的 KOL v3 scope 还存在发布门禁旁路。本轮只修复
这些 Gate/Replay 边界，不进入 B1–B7、方案 C 或真实 Task 9。

## 主要改动

- `backend/app/pi_runtime_poc/gate.py`：仅根据 published payload、canonical fields、
  field lineage、structured/narrative claims、fixture Evidence manifest、Version/Run/Session、
  availability 与 limitations 计算十项 hard checks；Evidence manifest 是唯一信任根，
  结果携带的 Evidence 副本还必须逐项匹配 fixture 的 value/unit/path。KOL v3 额外校验
  published/validation/version、候选 Evidence 身份、评分公式与叙事/限制披露；重复/未知/路径、
  scope、unit、candidate、Version 和零 DataTap 计数均 fail-closed。drilldown 必须提供前序
  published source artifact，并与 fixture 的 payload digest 精确一致。
- `backend/app/pi_runtime_poc/replay.py`：由 fake events 驱动 synthetic Evidence、当前
  Capability Pack snapshot、共享 Brand/Campaign/KOL Builder、`ArtifactPayloadValidator`、
  共享 publication validation、冻结的内存 Version 和正式 `export_artifact`；不读取预制结果，
  `hard_check_gate=PASS` 只由执行结果生成。导出摘要来自实际 XLSX bytes 的稳定规范化表示，
  只去除 renderer 写入的当前修改时间。
- `backend/app/agent_artifacts/offline_pipeline.py`、`publication_core.py`、`publishing.py`：
  抽取 direct/replay 共用的纯发布校验，并保留 direct publication 的候选 Version 与
  structured-claims 观测入口。
- `backend/fixtures/pi_runtime_poc/marketing_b0/`：仅保留脱敏 Evidence shape、scope、
  期望行为和事件输入；KOL fixture 使用完整 v3 scope，不保存待验证 hard-check 结论。
- `backend/tests/pi_runtime_poc/`：补充单位冲突、重复 Version、KOL scope/availability/评分维度、
  非法零调用、drilldown grounding、事件语义、Evidence/Version/路径/claims 篡改和共享入口行为测试。
- `docs/qa/pi-runtime-poc-rounds.md`：将 R2 前历史回放数字标为已覆盖，记录本轮真实共享链路
  与本地 synthetic 边界。
