# 品牌分析成功案例来源：ChatGPT + DataTap MCP

> 用途：人工审计和维护 `brand_analysis_success_v1.json`。本文件包含来源案例中的真实
> 品牌与日期，**禁止直接注入模型 Prompt**。Runtime 只能加载同目录 JSON 经 loader
> 生成的参数化投影。

## 案例结果

- 执行日期：2026-08-01；
- 分析对象：瑞幸咖啡；
- 分析周期：2026-07-01 至 2026-07-31；
- 平台：小红书、抖音；
- 结果：成功生成 8 Sheet 品牌声量和情感分析 Excel；
- 关键价值：专用趋势接口失败后，ChatGPT 没有终止，也没有伪造数据，而是使用已成功
  返回的按“日”维度数据构建趋势，并完成概览一致性核对和方法论披露。

## 来源任务 Prompt

```text
你是一名品牌社媒分析师。请基于 DataTap MCP，为“瑞幸咖啡”生成最近一个完整自然月的
品牌声量和用户情感分析报告，覆盖小红书与抖音。

先进行品牌标签匹配；匹配成功后必须使用 tag 作为检索目标。
获取各平台整体指标及环比、同比、按日趋势、平台×情感、内容类型、用户地域、热点话题、
热点用户和按互动排序的原帖。

不能补造未返回的数据；聚合指标按平台原始值求和；专用趋势接口失败时可以使用已成功
返回的“日”维明细构造趋势，但必须在报告和方法论中披露。结论只能描述证据支持的范围。
```

## 实际执行策略

1. 调用 `match_tags`，将品牌名称解析为供应商稳定品牌标签；
2. 分平台调用 `social_statistic_overview`，取得声量、互动、用户、情感及对比指标；
3. 尝试 `social_statistic_trend`：小红书返回上游错误，后续抖音请求被当时的本地熔断器
   拒绝；没有把失败解释为品牌无数据；
4. 冷却后改用 `query_analysis_data(dimensions=[日])` 获得完整日趋势；
5. 使用 `query_analysis_data` 补充平台×内容情感、内容类型和用户省份；
6. 使用热点话题、热点用户和原帖工具补齐洞察与热门帖子；
7. 确定性计算平台汇总、对比期、情感结构和趋势合计；
8. 核对日趋势合计与双平台概览总量一致；
9. 基于 8 Sheet 模板生成报告，缺失字段保留为空，并披露趋势替代来源和供应商口径。

## 工具结果摘要

| 阶段 | 工具 | 结果 | 后续决策 |
|---|---|---|---|
| 实体匹配 | `match_tags` | 成功 | 后续查询使用品牌标签 |

| 专用趋势 | `social_statistic_trend` | 上游失败/本地拒绝 | 不原样循环重试，寻找等价维度 |

| 情感/类型/地域 | `query_analysis_data` | 成功 | 补齐报告章节 |
| 话题/用户 | `query_hot_topics`、`query_hot_users` | 成功 | 支撑话题和达人层级洞察 |
| 热帖 | `query_raw_posts` | 双平台与分平台成功 | 填充真实帖子记录 |

## 可复用决策逻辑

- 标签匹配优先于宽泛关键词检索；匹配不唯一时先澄清；
- 核心指标按平台采集并保留原始口径；
- 专用工具失败后，根据错误类型选择拆平台、调整维度或换等价工具；
- `result_unknown` 不重放，`succeeded_empty` 不以相同参数重复；
- 趋势、概览和平台合计必须做一致性核对；
- 百分比不能直接跨平台平均，应恢复基数后聚合；
- 热点用户属于热点样本，不得扩写为全量达人盘点；
- 缺少商单标识时不得推断付费归属；
- 缺失数据保持 `null`，核心 Evidence 足够时可以发布 restricted 报告；
- 成功案例只示范策略，不构成固定工具顺序。

## 参数化要求

Runtime 注入前必须把品牌、日期、平台和对比模式替换为本 Run 的真实 Scope。禁止向模型
注入本文件中的“瑞幸咖啡”、2026-07 日期或来源报告真实汇总值。参数化、字段白名单和
长度限制由 `exemplar_loader.py` 负责，测试必须验证禁用值不出现在最终 Context。
